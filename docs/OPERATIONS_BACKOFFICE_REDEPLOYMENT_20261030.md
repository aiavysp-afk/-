# 上门养护运营后台：资料对照、对接审计与本轮部署

## 参考资料与运营结构

本次查阅的是厂商官方产品和帮助文档，不是市场份额或行业大数据统计，不据此编造经营效果。

- [有赞本地生活](https://www.youzan.com/local-life)：消费者预约、PC商家管理、人员排班、预约提醒在同一条业务链中协作。
- [Fresha 服务目录管理](https://www.fresha.com/help-center/knowledge-base/catalog/77-archive-and-delete-items-in-your-service-menu)：提供项目归档/删除，已有预约继续保留。

据此采用“登录入口 → 项目管理 → 技师审核及排班 → 客户预约 → 订单履约 → 售后与账本”的运营结构。资金流水、历史订单、审计记录使用业务动作或只读查询；不提供无差别硬删除。

## 本轮实际修复

1. 登录保留已有账号密码及本人短信验证，首次设置、账号设置与常用设备说明默认折叠，避免把登录与首次开户混在一起。成功进入经营概览，敏感操作仍执行原验证规则。
2. 服务项目补齐真实新增、编辑、删除确认、上下架、分类选择、状态筛选及数量统计。价格、时长、简介、介绍、流程和服务边界均可填写；提交前核对内容。分类沿用当前3种业务类型，没有新增可自由命名的分类模型。
3. 修复私有后台网关原本没有放行已有项目 PATCH 接口的断点，并增加精确的集合 POST、单条 PATCH/DELETE；没有开放任意后台路由。
4. 新增默认下架；同一创建编号可安全重试。编辑/删除传递更新时间快照；并发冲突不覆盖他人数据。删除要求项目已下架，且不存在订单、预约或技师引用；历史记录保留。
5. 技师资料页突出“补充资料 / 审核发布”，将一次性邀请折叠为备用方式，并明确资料、项目、审核、发布、排班的营业流程。

## 上线验收原则

PC登录配置可用、接口返回200、源码或隔离测试通过，不等于用户本人已完成登录，也不等于所有真实经营条件已满足。真实技师的资料补齐、审核、发布、项目匹配及排班完成后，才能验证客户预约与真实接单闭环。
