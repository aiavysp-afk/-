# 后台用户名与短信二次验证部署

## 行为和边界

- 微信小程序确认加动态码仍是主登录方式；账号密码登录支持本人设置的用户名或既有绑定手机号。
- 用户名为 4–32 位 ASCII 字符，以字母开头，其余为字母、数字、下划线或短横线，统一去首尾空格并转为小写。
- `admin` 只是建议登录名，不创建管理员、初始密码或任何新权限。新增可空字段，不回填既有账号。
- 本人先微信登录、绑定动态码并完成当前动态码验证，才可在“账户安全”设置用户名和 12–128 位新密码。密码及验证码仅由本人在页面输入，不发到聊天。
- 短信只能发送给服务端保存的已验证手机号。用户名与手机号共用账号锁定、登录限流和短信额度，不另开预算。
- 短信二验和 7 天设备信任仅提供登录保证，不替代审核、发布、资金或权限变更所需的新鲜动态码。
- 客户短信会话不获得后台或技师权限。用户名冲突统一拒绝；修改密码会撤销其他后台会话、未完成挑战及全部设备信任。

## 部署顺序

1. 运行全仓库测试、类型检查和构建；运行 `node --test scripts/enable-production-staff-password.test.mjs`。
2. 用现有 `scripts/verify-staff-auth-isolated.ps1` 的 `staff` 验收模式创建一次性专用数据库，应用全部迁移并运行真实存储验收。禁止使用正式库 URL 或正式用户做测试夹具。
3. 提交并推送精确版本，按现有脚本依次部署 API、私有后台、Nginx，保留当前电脑 IP 白名单。
4. 确认 `20261016040000_staff_password_login_alias` 已应用。该迁移只新增可空唯一用户名和格式约束。
5. 在已部署的精确版本目录中运行：

   ```sh
   node scripts/enable-production-staff-password.mjs --confirm-enable-staff-password <40位已部署版本SHA>
   ```

   脚本只把 `STAFF_PASSWORD_LOGIN_ENABLED` 从关闭改为开启，保留其他配置原始字节。要求微信、MFA、设备信任、现有阿里云验证码发送、客户短信登录和明确的每日限额已就绪；不会配置密钥、设置密码、创建账户或发送短信。

6. 检查后台账号密码开关开启、客户两种登录仍开启、微信后台登录开启、设备信任为 7 天、匿名受保护请求仍为 401。当前共同验证码请求上限为每日 20 次，不自动充值。
7. 本人完成用户名/密码设置后，再由本人验收密码加短信登录。自动探针和隔离验收不能等同于正式用户已设置 `admin` 或已完成真人登录。

## 回滚

启用脚本持有部署锁，固定校验 root 所有、0600 的正式环境文件和服务运行版本；同目录原子替换前保留原样备份。重启或探针失败时，仅在配置与 inode 未被外部修改的情况下恢复原样并复验；检测到外部漂移时拒绝覆盖，报告人工检查。备份含敏感配置，只留服务器受保护目录，不下载或提交。

应用回滚可使用现有部署脚本的已验证机制；新增数据库列向后兼容，不删除或回填正式凭据数据。保持微信登录和动态码保护，不将认证失败处理为自动创建身份。
