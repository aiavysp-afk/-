# 验证器丢失受审恢复

日期：2026-10-04。

## 交付范围

本功能只解决已经绑定TOTP的工作人员丢失验证器后的安全恢复，不提供绕过MFA的万能入口：

1. 申请人必须在微信小程序重新完成登录，并在五分钟内选择自己的有效工作人员组织发起申请。
2. 服务端要求申请人当前确有已启用旧因子；每人同时只能有一笔待复核申请，申请30分钟过期，24小时最多三次。
3. 复核人必须是另一名同组织ADMIN，当前后台会话必须已经完成MFA。申请人不可复核自己。
4. 复核时在事务内重新检查复核人权限、申请人membership、原微信来源会话、旧因子和期限，不依赖页面快照。
5. 批准会在同一事务中删除旧因子、撤销申请人全部会话、把申请置为APPROVED并写审计。申请人随后必须重新微信登录并重新绑定。
6. 拒绝保留旧因子和会话；取消只能由发起申请的原会话完成。已结束申请不能回到PENDING。

## 数据和并发保护

第16批migration新增`MfaRecoveryRequest`和五态枚举。部分唯一索引限制每个申请人只有一笔PENDING；数据库检查约束禁止自审及字段/状态不一致；触发器固定组织、申请人、来源会话、创建与到期时间，并禁止终态回滚。批准事务按固定顺序锁定用户、会话和申请记录，因此两个管理员同时批准时恰好一个成功，另一个得到409，不会重复执行撤销。

记录保存申请组织、申请人、来源会话ID、复核人、复核会话ID、原因、时间和终态；不保存动态码、验证器明文密钥、微信code或Bearer token。审计记录申请、批准、拒绝、取消和过期动作。

## 用户入口

- 小程序“我的”进入“验证器丢失恢复”，页面明确说明批准后的影响；提交前强制重新微信登录。
- 管理后台“账户安全”只对同组织ADMIN展示队列，并且必须先用管理员自己的验证器提升当前会话。批准与拒绝均需浏览器明确确认。

## 验证方法

```powershell
$env:MFA_RECOVERY_TEST_DATABASE_URL='postgresql://zhongyuan:local_only@127.0.0.1:5432/zhongyuan_daojia_test?schema=public'
pnpm build
pnpm --filter '@zydj/api' test:mfa-recovery
```

脚本拒绝普通远程库和生产库；只创建合成身份并在结束时清理。覆盖新鲜来源会话、严格请求体、并发唯一申请、频率限制、自审/跨组织/未MFA拒绝、并发一次批准、全会话撤销、新因子重绑、拒绝、原会话取消、来源注销、资格撤销、过期、终态触发器和无秘密审计。

## 上线前人工演练

- 两名不同的真实ADMIN分别用真实微信身份和不同验证器完成登录；不得共用手机或TOTP种子。
- 申请人用小程序新登录发起，复核人线下核对本人身份后在后台批准；确认所有申请人旧手机/电脑会话立即401。
- 申请人再次微信登录，绑定一个全新验证器并完成MFA；确认旧动态码永久无效。
- 分别演练拒绝、申请人取消和30分钟过期；核对审计的申请人、复核人、组织、时间和结果。
- 确认监控能发现异常频率、连续拒绝和大量会话撤销。任何演练都不得使用真实支付开关。

该功能的代码或隔离测试通过不等于真人身份、设备保管、值班制度或公开生产环境已经验收。
