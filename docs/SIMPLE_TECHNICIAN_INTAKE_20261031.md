# 技师入驻简化说明

本轮按“指令 3”实施，小程序只收集入驻申请，不建立新的技师登录注册体系。

## 使用流程

1. 首页下方点击“技师入驻”，或使用原入驻页的小程序路径。
2. 填写姓名、手填手机号，阅读隐私说明并选择一张清晰的本人职业资质证书照片；支持拍照和相册。
3. 点击“提交入驻申请”，服务端保存后显示“提交成功 · 待审核”。
4. 后台进入“技师审核”，刷新后查看新申请；证书点击后在当前页私密预览，可以通过或拒绝。

不要求微信手机号授权、短信验证码、密码、配对码或已有客户账号。不在小程序显示技师名单、形象照列表、接单工作台和收入界面；旧入口只做兼容跳转。客户项目和订单保留，项目预约不再先经过技师列表页。

## 数据和审核边界

- 新数据表为 `TechnicianIntakeApplication`，与旧技师档案分开，不伪造用户或技师成员身份。
- 姓名、手机号、证书照片在服务器加密保存；手机号是手填的，后台明确显示“本人填写，未验证”。
- 默认状态 `PENDING_REVIEW`，审核后仅改为通过或拒绝。不创建技师账号，不自动发布、排班或接单。
- 后台原待审核申请继续保留；列表将两类记录合并，表格仍为四列、通常三个业务按钮。
- 证书没有公开图片链接。读取必须使用现有管理会话、当前组织和技师管理权限，访问会留痕；审核继续要求现有动态码及资料版本检查。
- 匿名入口只接受一次提交，不提供申请名单、证书或个人资料查询接口。成功回执不包含姓名、手机号或照片。
- 图片最多 512KB，服务器校验格式、限制像素并去掉定位等附带信息；接口按 IP、手机号和全局限制频率。
- 网络超时可在原表单再次提交，未修改内容时沿用同一提交标识，避免重复建档。资料不写入小程序的长期本机存储。

## 验证情况

匿名表单的必填校验、用户主动选图、防重复点击、失败重试、成功回执及关闭页面后的响应隔离已检查。后台对新旧记录的审核路径、组织隔离、动态码和证书私密预览已检查。前后端构建、数据表静态校验和请求转发检查通过。没有替用户上传真实证书，也没有审核真实人员。

开发者工具中，新表单已实际显示，空表单点击提交会提示填写姓名，且不发送申请。当前 Windows 模拟器基础库 3.8.12 同时出现微信内部脚本的渲染异常；未确定根因或真机影响，保留为验收限制。未将模拟器画面或自动测试当成真实手机完成证书提交和后台审核的证据。

微信提审另见 [微信小程序提审风险说明](WECHAT_REVIEW_RISKS_20261031.md)。尤其需要先核实上门按摩及技师入驻的类目准入；简化表单不等于已经具备提审营业资格。本轮不自动提交微信正式审核或发布。
