# 微信支付通知与对账实现

日期：2026-10-03。此文记录代码与本地验证边界，不代表线上收款验收。

## 通知与查单

`POST /v1/payments/wechat/notify` 不使用客户会话，而是验证微信平台签名。Nest/Fastify 启用原始 Buffer 保留；验签串严格使用时间戳、随机串、原始报文和换行。平台公钥 ID 必须完全匹配，证书模式检查序列号和有效期。超过五分钟、缺失/重复头、SIGNTEST 探测、签名失败均拒绝。资源解密使用 APIv3 密钥、AES-256-GCM、nonce 与附加数据。

解密后核对 AppID、商户号、JSAPI 类型、CNY 金额、商户单号和微信流水。数据库先锁订单，再读取当前支付状态；同一事务更新支付/订单/预约并写支付事件、订单事件、审计和 Outbox。成功提交或相同流水的幂等重复返回空 204；失败返回非 2xx 与通用 FAIL，不回传密文、用户信息或签名材料。

客户本人可调用 `POST /v1/payments/:id/reconcile`。服务器对 GET 查单签名并验证响应，成功使用同一事务处理；其他状态只作为渠道事实返回，不因一次 NOTPAY/网络异常释放资源。没有主动轮询定时任务，当前由调用方发起核实。

若订单已取消、支付截止时间已过或预约已释放，支付仍记录 `SUCCEEDED`，同时标记 `FULFILLMENT_REVIEW_REQUIRED` 并写待处理 Outbox。订单保持取消或转为取消，不恢复冲突预约。该待处理事件尚需接入运营界面、消息消费与人工安排/退款工作流。

Mock 超时工作器跳过微信支付记录。真实微信支付需补充主动查单、渠道关单、再核实后释放的完整流程；当前预下单关闭，因此本地不存在可实际发起支付的微信订单。

## 日账单核对

`POST /v1/admin/organizations/:organizationId/payments/reconciliation/:date` 需要指定组织 `finance.approve` 权限。日期按北京时间且必须已结束。账单元数据先验签；下载限定官方 HTTPS 域名与账单路径，拒绝跳转，核对 SHA1 并限制文件/解压大小。账单文件不含微信响应签名，文件完整性来自已验签元数据中的摘要。

解析 ALL 账单时去掉 Excel 防科学计数法的前缀，金额以 BigInt 整数分运算，退款手续费允许负数；要求明细数量与汇总一致。历史不兼容表头、未知状态或破损文件需人工处理。

报告逐笔列出金额/流水不一致、本地未确认、重复渠道单、渠道漏单和待查退款；不会自动修改支付或退款状态。退款账单行表示退款发起事实，不能代替当前退款结果查单。原始账单中的 openid、银行、商品等字段不进入审计。共享商户下跨组织或不能归属本组织的渠道行只生成商户范围待核实标志，不披露其流水；该标志存在时不能显示全匹配。

当前在线核对最多处理 10,000 条本 AppID/商户明细。报告写入审计，尚未接入定时账单任务、财务界面、退款账本和实际渠道净结算核对。

## 退款范围

退款记录、申请/独立复核、累计额度占用、固定业务号、签名通知/原单查询/恢复租约、成功一次记账已完成。真实退款POST由 `WECHAT_PAY_REFUND_ENABLED=false` 默认关闭；批准后先提交本地PROCESSING记录，再调用签名POST；网络不确定保留额度并转UNKNOWN，不自动重发POST或生成新单号。完整范围与接口见 [退款实现](REFUND_IMPLEMENTATION.md)。真实JSAPI预下单仍为503门禁，未发起实际资金交易。
