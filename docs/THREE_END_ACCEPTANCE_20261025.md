# 三端入驻与登录补充验收（2026-10-25）

## 本轮改动

- PC 后台沿用绑定手机号/账号、密码和短信验证，首次设置页明确提示已有密码应返回登录，不重置账号或权限。
- 后台新增入驻资料补录：真实姓名、城市、区域、意向时段、擅长项目和简介。限同组织有技师管理权限的工作人员；服务端检查版本，保存转草稿后重新审核。照片和证件沿用现有上传/查看入口。
- 技师网页沿用手机号短信登录、草稿、照片/私密证件上传、提交待审核和本人工作台。
- 仅通过手机号网页入驻、从未绑定微信且无管理凭据的技师，可经微信官方手机号授权绑定首次微信身份到原账号。已绑定其他微信或有管理身份的账号不允许走此通道改绑。
- 小程序新增主动订阅订单提醒入口。服务端重查真实支付及指派关系，持久化一次发送状态；不把微信受理当作送达，不对未知结果重复发送。短信、微信消息在隔离测试中使用替身，禁止向真实用户发送测试通知。

## 开通依赖

- 用户已明确本次尚未为欠费的阿里云短信账户充值。短信配置开关启用不能证明能收码；必须余额转正并由本人完成手机收码登录验收。
- 微信订单订阅需要真实小程序订阅模板与用户主动同意。模板配置齐全前 `TECHNICIAN_WECHAT_NOTIFICATIONS_ENABLED` 保持默认 false。
- 模板环境变量：`TECHNICIAN_WECHAT_TEMPLATE_ID`、`TECHNICIAN_WECHAT_SERVICE_FIELD`（thing 字段）、`TECHNICIAN_WECHAT_TIME_FIELD`（time 字段）、`TECHNICIAN_WECHAT_NOTICE_FIELD`（另一 thing 字段）。需与公众平台真实模板对应。
- 开发版/体验版测试用 `TECHNICIAN_WECHAT_MINIPROGRAM_STATE=trial`；正式发布后才用 formal。上传、正式审核、用户订阅、消息受理和送达是不同步骤，不能互相替代验收。

## 验收入口

- API 单元/接口测试：`pnpm --filter @zydj/api test`
- 管理端与网页端测试：对应包的 `test`、`build`
- 私网代理及小程序静态检查：`node --test scripts/*.test.mjs`
- PostgreSQL 隔离验收：`apps/api/scripts/verify-technician-phone-flow.ts`。必须传专用数据库地址；真实图片解码、上传、审核、同一账号绑定与通知 SQL 在事务内验证并全量回滚。不得指向生产库。

本文件记录实施边界，不代表真实短信、微信模板、体验版上传或正式发布已经完成。部署结果以当次发布日志和实际验证为准。
