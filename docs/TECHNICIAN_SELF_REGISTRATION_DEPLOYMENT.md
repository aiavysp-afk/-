# 中原到家：技师自主入驻部署方案

## 本次确定的流程

微信小程序授权登录 → 验证本人手机号 → 填写照片、真实简介和擅长项目 → 提交审核 → 后台通过/退回 → 审核通过后再次微信登录直接进入本人工作台。

- 不再要求新技师填写邀请码、配对码、复制登录令牌。
- 姓名、年龄段非必填，可留空，由后台后续补录；不把微信内部账号名称自动公开。
- 草稿、待审核、退回状态只能维护本人资料、查看审核结果，不开放订单及接单。
- 退回必须填写原因，技师修改后重新提交；后台审核带版本核验，防止批准过期内容。
- 审核通过与技师身份绑定在同一个数据库事务中；不会恢复停用账号，不允许跨组织绑定。
- 已批准才可进入本人工作台；公开展示另需后台发布，客户可预约还需真实有效排班。
- 修改已通过资料会回到草稿并要求重新审核。旧订单/账务不删除。

## 三端同步

小程序入驻页和照片页写入已有 TechnicianProfile / TechnicianPhoto 数据；后台“技师管理 → 微信自主入驻审核”读取同一数据库，不复制多份资料。后台支持照片预览、资料编辑、审核通过、退回修改、发布/下架。

原生工作台读取本人订单和排班，接单/出发/到达/开始服务/完成服务使用现有服务状态接口；订单进度同步客户与后台。只返回本人订单，不开放后台接口，不显示代付人私人身份。

网页 https://mtsc.top/technician/ 是 H5，不能直接调用小程序 wx.login。主入口引导“中原到家小程序 → 我的 → 设置 → 技师入驻与登录”；网页辅助登录保留为可选，不是新技师入驻前置步骤。未配置公众号 H5 OAuth 前，不宣称网页直接微信授权可用。

## 接口与权限

- GET /v1/technician/onboarding：读取本人申请及是否可进入工作台。
- POST /v1/technician/onboarding：真实微信会话和已验证手机号创建本人草稿，无客户端组织、角色或他人账号参数。
- /v1/technician/workbench/profile 及照片、提交审核接口：本人资料。
- GET /v1/admin/organizations/:organizationId/technician-applications：本组织入驻申请。
- POST /v1/admin/organizations/:organizationId/technicians/:technicianId/profile/approve：审核通过，提交 expectedVersion。
- POST .../profile/reject：退回，提交 reason 和 expectedVersion。
- 后台仍需现有私网、组织权限和 MFA；原生技师仅使用已审核微信身份维护本人服务订单。浏览器工作台保留原 MFA 要求。

当前单平台只有一个包含已发布服务的组织，由服务器确定归属。出现零个或多个组织时拒绝自动注册，需要先明确平台组织；不由客户端任意选择租户。

## 部署顺序

1. 编译和测试：接口合同、身份来源、手机验证、草稿/审核/退回、越权、后台照片预览、工作台本人订单、小程序登录回跳与全部页面事件绑定。
2. 提交并推送不可变版本 SHA；不纳入本地 output、凭证、二维码运行记录。
3. 生产 API：下载同一 SHA，构建并检查照片解码；备份真实数据库并核验备份，再执行增量迁移（新增 selfRegistered 标志，默认 false），启动新 API 并验证健康、服务数据。
4. 同一 SHA 部署私有管理后台，再更新网关白名单；公网后台仍保持维护屏蔽，匿名入驻接口应 401，非法方法应 403/404。
5. 更新技师 H5 入口；小程序重新编译，上传开发版、生成直达入驻页预览二维码。正式发布仍需微信平台审核/发布步骤。
6. 验收后记录 SHA、备份、服务状态、网关探针、二维码与待完成的真人授权核验。

## 人工验收（必须真实账号）

1. 新微信账号验证手机号后进入资料页，无配对码；上传本人已授权照片，简介/擅长真实填写，姓名/年龄留空仍可提交。
2. 后台同组织管理员能查看照片和申请；技师此时不能查询订单或接单。
3. 后台退回后，技师能看到原因并修改重新提交。
4. 后台本人确认审核通过后，技师第二次微信登录直接进入工作台；停用账号和其他组织账号不可进入。
5. 资料需发布及排班后才显示可预约，不伪造在线技师、评价或排班。
6. 本人指派订单的真实服务动作同步三端；不以生产测试订单、支付或假回调冒充验收。

微信转账额度补充材料按此前要求继续暂停；本次不修改提现规则、发放红包、充值账务、商户额度或付款能力。
