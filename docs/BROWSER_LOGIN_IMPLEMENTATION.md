## 使用路径

1. 受控环境配置`STAFF_BROWSER_LOGIN_ENABLED=true`，默认false。电脑打开后台“账户安全”，点击发起登录。
2. 电脑显示22位随机配对码和六位核对数字，有效三分钟。浏览器秘密只留组件内存，不能复制到手机或放URL中。
3. 中原到家小程序“我的 → 后台登录确认”，手动输入电脑配对码，点击“重新微信登录并核验配对”。实际微信模式沿用服务端code2Session；客户或未授权人员不能批准后台身份。
4. 手机输入电脑六位数字，再明确确认“是本人主动发起的电脑登录”。不处理他人、客服或陌生人发送的配对码，不自动批准扫码或URL参数。
5. 原电脑点击“我已在小程序确认”。只有原浏览器秘密能领取一个全新会话；它不是手机令牌，不继承手机MFA，之后必须独立绑定/验证TOTP。

这是自有系统的受控跨设备交接，参考[RFC8628的分离配对码/设备凭证与确认机制](https://www.rfc-editor.org/rfc/rfc8628)，**不是通用OAuth服务器，也不声称符合完整OAuth设备协议**。微信官方文档入口：[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)，本轮工具未能读取该官方页面；客户端流程已用隔离HTTP替身验证，不能据此宣称官方真机验收完成。未添加公众号网页授权或微信开放平台扫码登录，不虚构相关授权范围。

## 固定边界

- 128bit配对码、256bit浏览器秘密，秘密及核对数字仅存领域分离HMAC；不写URL、审计或日志。所有成功交接响应no-store，严格拒绝额外身份/角色/redirect参数。
- 批准和领取时均在User→源Session→Challenge的锁序内重新核验ACTIVE人员/成员资格、五分钟内新小程序会话、渠道来源和未注销/未过期。遗留、后台浏览器或错误provider会话不能作为小程序第一因子。
- 两实例/并发领取只有一个新Session，另一次409。新会话最多一小时且不超过源会话期限，mfaVerifiedUntil为空。领取响应丢失时只能重建配对，不能再次颁发；新Session无需依赖手机继续在线，领取后注销手机不自动注销电脑，电脑须独立注销。
- 五次核对错误持久化并取消配对；取消、消费和审批身份不可回退/替换，DB触发器限制状态及固定期限。DB管理员仍是信任边界，不声称防止root直接篡改或删除数据。
- PostgreSQL共享限流：全局创建1000/小时、真实socket peer60/小时、工作人员核验30/10分钟；轮询两秒间隔。拒绝通过X-Forwarded-For伪造peer绕过。代理后的用户共享预算，正式容量规划和可信代理配置须另行验收。
- 超过到期24小时的配对、到期计数在后续创建时仅清理本模块临时表，永久会话和审计不删除；无访问时不自动清理。没有后台任意恢复、重置MFA或绕过审核接口。
- production模式必须微信provider；电脑接口还要求精确允许的HTTPS Origin，不能通过CORS任意回调。私有预览代理已转发Origin，未改变公网Nginx。
- 后台令牌改用sessionStorage并退役旧localStorage入口，页面离开清理配对秘密；异步旧响应不能覆盖新账号，弃用成功会话尽力注销。已过期会话会返回登录页，注销遇401可清除本机失效状态；网络异常不冒充注销成功。sessionStorage仍受同源XSS影响，并非HttpOnly设备绑定凭证，正式部署必须完成CSP/依赖/反钓鱼审查。
