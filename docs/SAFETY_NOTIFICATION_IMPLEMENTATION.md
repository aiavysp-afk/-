# 安全通知 Outbox 可靠投递

更新日期：2026-10-05

## 已实现范围

- 安全事件创建和主岗超时升级分别生成主岗首报、备岗升级两类 Outbox 事件；事件保存组织、责任人快照和固定事件类型。
- 工作者通过 PostgreSQL `FOR UPDATE SKIP LOCKED` 获取短租约，多实例并发只能领取一次；调用渠道前先记录尝试次数和开始时间。
- 可重试失败采用指数退避，最多 8 次；渠道返回未知结果或进程可能已经调用渠道但未落库时直接进入人工复核，禁止盲目重复发送。
- 阿里云返回 `OK` 和 `BizId` 仅记录为“渠道已接受”，不宣称手机已收到。渠道跟踪标识只保存在数据库，不通过管理接口公开。
- 第 20 批迁移增加独立送达状态和查询调度。只读回执工作者按 `BizId`、单个加密值班号码与中国时区发送日期调用阿里云 `QuerySendDetails`；状态 1/2/3 分别记录等待、失败、送达。查询不读取或保存短信正文，明文号码不落日志或接口。
- 回执查询最多 48 次并指数退避到 30 分钟，超过次数或官方 30 天查询窗口后标记 `UNKNOWN` 交人工复核；查询失败不会重新提交短信。
- 管理员可以为本组织有效 `SAFETY_DUTY` 成员录入中国大陆手机号。号码使用现有 AES-256-GCM 数据密钥加密保存，列表只显示“已配置/未配置”，审计不记录号码或后四位。
- 值班人员可查看本组织通知的等待、渠道接受、人工复核状态；只有管理员能在查明原因后把死信恢复为等待状态，每次操作写审计。
- 自动投递使用独立 `SAFETY_NOTIFICATION_DISPATCH_ENABLED` 门禁，默认 `false`。设置 provider 或填入凭据不会自动开启。
- 回执查询使用独立 `SAFETY_NOTIFICATION_RECEIPT_QUERY_ENABLED` 门禁，默认 `false`。它只允许查询已被渠道接受的记录，不授权发送。
- 后台摘要统计投递积压、等待回执、送达、失败、未知和死信；未投递超过 5 分钟、回执等待超过 15 分钟或任何失败/未知/死信都会显示人工关注状态。

## 失败语义

| 情况                           | 处理                                                          |
| ------------------------------ | ------------------------------------------------------------- |
| 渠道明确拒绝或临时未就绪       | 指数退避，最多 8 次                                           |
| 响应缺失、超时或结构不可信     | `DEAD_LETTER`，人工核对渠道后决定是否重试                     |
| 进程在渠道调用后、落库前中断   | 租约过期后标记 `PREVIOUS_ATTEMPT_OUTCOME_UNKNOWN`，不自动重发 |
| 责任人、事件、号码或载荷不一致 | `DEAD_LETTER`，不向其他号码降级发送                           |
| 渠道接受                       | 标记 `ACCEPTED/PENDING`，进入只读回执查询                     |
| 回执状态1或暂未查到明细        | 指数退避继续查询，不重发短信                                  |
| 回执状态2                      | 标记 `FAILED`，保留运营商错误码供人工处理                     |
| 回执状态3                      | 标记 `DELIVERED`；仍不等于真人已响应                          |
| 查询耗尽或超出30天窗口         | 标记 `UNKNOWN`，停止自动查询并要求人工复核                    |

## 固定短信模板变量

代码只发送 `orderNo`、固定事件分类 `category`、固定阶段 `stage` 和确认截止时间 `deadline`。上线前必须在已审核模板中逐项核对变量名、长度和非医疗/非公共急救措辞；不要把用户地址、电话、自由文本或健康信息放入模板。

## 验证

第 19 批迁移 `20261005090000_safety_notification_outbox` 建立可靠投递，第 20 批 `20261005153000_safety_delivery_receipts` 增加送达回执状态、查询次数、调度时间及数据库约束。专项命令：

```powershell
$env:SAFETY_NOTIFICATION_TEST_DATABASE_URL='postgresql://zhongyuan:local_only@127.0.0.1:5432/zhongyuan_safety_test?schema=public'
pnpm --filter @zydj/api test:safety-notifications
```

脚本只允许两个本机隔离测试库，使用替身渠道，不发送真实短信，并清理自己的合成数据。覆盖并发单领、接受记录、投递退避、最大次数、未知结果死信、崩溃不确定状态隔离、号码加密、回执状态约束、监控摘要和管理员人工重试；单元测试另覆盖回执查询签名、等待/失败/送达映射、查询退避与耗尽。

## 正式启用顺序

1. 备份数据库，在副本应用全部 20 批迁移，再部署代码；保持 `SAFETY_NOTIFICATION_DISPATCH_ENABLED=false` 和 `SAFETY_NOTIFICATION_RECEIPT_QUERY_ENABLED=false`。
2. 管理员配置两名不同自然人的主备岗及各自真实值班号码，完成权限、交接和号码接听核验。
3. 在阿里云确认签名和模板审核有效，使用受限 RAM 身份与受控密钥配置；模板变量必须与上文完全一致。
4. 在非公开受控环境先启用 `SMS_PROVIDER=aliyun` 与 `SAFETY_NOTIFICATION_RECEIPT_QUERY_ENABLED=true`，用既有受理记录验证只读回执查询；再单独启用 `SMS_SEND_ENABLED=true` 做受控提交测试。
5. 完成主岗首报、超时备岗升级、真人确认、公共应急转介、积压/死信告警和失败回退演练并签字。
6. 只有以上全部通过，才可设置 `SAFETY_DUTY_CONFIRMED=true` 和 `SAFETY_NOTIFICATION_DISPATCH_ENABLED=true`。两个开关均须可快速关闭；不能与支付开关联动。

当前代码完成可靠提交、只读送达回执查询和后台积压/失败可观测性，但没有调用真实阿里云接口，也未完成真人主备短信演练。因此真实自动发送、回执查询与公开经营门禁继续保持关闭。
