# M1 身份与权限矩阵

## 身份边界

- 小程序登录只接收微信一次性 `code`；`openid` 由服务端换取，前端提交的用户 ID、组织 ID 或角色均不作为身份依据。
- 新微信身份固定创建为 `CUSTOMER`。工作人员权限来自数据库中的有效 `StaffMembership`，不能通过登录请求自选。
- 原始微信身份标识使用 AES-256-GCM 加密保存，检索使用带服务端 pepper 的 HMAC；会话令牌只向客户端返回一次，数据库仅保存令牌摘要。
- 每个工作人员权限限定在其 membership 对应的组织；跨组织访问默认拒绝。

## R1 角色权限

| 角色              | 主要允许                               | 明确不允许                         |
| ----------------- | -------------------------------------- | ---------------------------------- |
| CUSTOMER          | 本人资料、本人占位/报价/订单、公开目录 | 后台目录维护、调度、财务、安全值班 |
| THERAPIST         | 本人资料、本组织必要订单读取           | 修改目录、调度他人订单、财务审批   |
| OPERATOR          | 本组织目录、订单读取、审计摘要         | 财务申请/审批、跨组织数据          |
| DISPATCHER        | 本组织排班读取与维护、订单读取与调度   | 修改资金事实、伪造服务完成         |
| FINANCE_REQUESTER | 本组织财务申请                         | 审批自己的申请                     |
| FINANCE_APPROVER  | 本组织财务审批与审计                   | 发起同一笔财务申请                 |
| SAFETY_DUTY       | 本组织安全事件与必要订单资料           | 日常导出高敏感信息、财务操作       |
| ADMIN             | 所属组织全部后台权限                   | 自动获得其他组织权限；绕过审计     |

当前已实现权限计算与组织范围断言。排班写入仅开放给所属组织的 `DISPATCHER` 和 `ADMIN`；`OPERATOR` 不能借目录权限修改排班。安全值班表仅允许所属组织 `ADMIN` 配置，主备必须是两个不同且有效的 `SAFETY_DUTY` 成员；安全事件读取/确认/关闭要求本组织 `safety.respond`，但事件内部还会按快照责任人和阶段限制为主岗或备岗，`ADMIN` 也不能冒充事件确认人关闭。后台工作人员邀请、角色变更审批和敏感导出审批将在后续管理端切片实现，在此之前不得通过直接前端参数授予权限。
