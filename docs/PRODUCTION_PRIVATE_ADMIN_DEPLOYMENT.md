# 正式数据库私有管理入口

此入口部署管理后台的照片上传、草稿预览、审核、资料修改、排班与既有业务页面，不发布未审核技师，不创建虚假身份，不启用提现，也不修改金融规则。验收数据库及 3210 / 3212 / 3213 服务保持不变。

## 隔离与认证

- 正式管理静态服务仅监听 `127.0.0.1:3222`，固定代理正式 API `127.0.0.1:3220`。
- `https://admin.mtsc.top` 沿用既有 TCP 来源私网白名单，公网始终 `503 maintenance`。白名单、微信配对、真实 HTTPS Origin、组织权限和新鲜 MFA 均未放宽。
- 管理端使用同源 `/v1`；浏览器配对需本人在微信小程序确认，再完成后台 MFA。直接访问 HTTP loopback 不能代替 HTTPS 登录。
- 精确方法/路径白名单只包含管理页面所需的既有接口；客户下单、充值、公众照片、技师本人接口、开发接口和未知 `/v1` 均不代理。
- Authorization / Idempotency-Key 原样转发；Origin 原样验证、转发，缺失时不补造。空请求不发送 `application/json`，避免空 JSON 解析报错。
- 照片草稿经鉴权二进制接口预览，允许 `blob:` 图片；不把草稿改成公开照片。不转发上游 Cookie、Location 或任意 CORS 响应头。

## 部署顺序

在已验证正式服务器，以 exact 40 位提交 SHA 执行 `scripts/deploy-production-private-admin.sh <SHA>`，随后执行同一版本 `scripts/deploy-production-nginx.sh <SHA> <已验证的现有 vhost 路径>`。

独立目录为 `/opt/zhongyuan-daojia-admin/releases/<SHA>`；运行身份沿用现有非 root `zydj`。从正式同 SHA 发布目录复制时排除依赖和构建产物，绝不在运行中的 API 发布目录安装依赖。否则仅下载 exact SHA 源码并独立构建。前端构建不加载 API 环境秘密。

构建由 root 使用现有验收目录中的工具运行，但正式管理服务仅复用 `/usr/bin/node`，不能使用另一个服务账号专属的验收 runtime。发布前以 `runuser -u zydj` 在清空的环境中实际验证系统 Node 可执行且至少为 22；不增加生产账号组成员、不调整验收目录权限。

脚本只读取生产身份和既有 CORS 开关作为门禁，不修改它们；不执行数据库迁移或初始化。unit 与 previous current 链接都保存恢复记录，启动或探测失败自动恢复此前版本。所有删除仅针对失败部署创建的精确链接/新 unit，没有递归删除。

验收包含：loopback 页面 `200`、未登录管理资料 `401`、未知路径 `404`，真实证书 HTTPS 私网入口 `200`，独立外网客户端管理入口 `503`。阿里云 NAT 主机私网源地址不能证明公网拦截，网关脚本会明确提示需要独立外网验证；发布负责人必须在服务器外部实测管理首页 `503` 与 API 管理路径 `403`，不符合时恢复保存的精确 vhost 备份及管理 unit/current 链接。

还需用户通过已有 VPN / 可信私网访问本人配对和 MFA，检查照片上传审核流程；未完成此本人验收前不宣称资料已公开。
