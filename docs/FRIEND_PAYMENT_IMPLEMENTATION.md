# 好友代付交付与验收

日期：2026-10-10。仅支持现有小程序微信支付体系，不接入个人转账、支付宝或现金代付。

## 用户流程

确认订单页「微信支付 / 好友代付」并列。下单人选择好友代付后先创建真实待支付订单，进入代付分享页，通过原生微信分享按钮发给好友。好友登录本小程序的微信身份，核对项目、时长、数量、服务商户、预约时间和服务器确认金额后，用自己的微信付款。

分享页不展示下单人姓名、电话、详细地址、定位或备注。姓名与年龄段不从其他资料推断。订单权益、取消及申请退款权限始终归原下单人；批准退款原路返回实际付款微信账户，不转入下单人余额。

下单人的消息页展示服务端持久代付通知；打开分享页时最多自动查询一分钟，离开后停止查询。没有配置微信订阅模板或取得订阅授权，因此这不是微信离线推送。原订单页仍可查看付款与履约状态。

## API 与权限

| 接口 | 权限及作用 |
| --- | --- |
| POST `/orders/:id/friend-payment` | 仅下单人，待支付且真实预约有效；生成高熵微信分享路径 |
| GET `/friend-payments/:token` | 已登录微信用户，返回脱敏订单摘要和可支付状态 |
| POST `/friend-payments/:token/payment-intent` | 原下单人除外；订单锁内绑定唯一代付用户和本 AppID 微信身份 |
| GET `/friend-payments/:token/payment-intent` | 仅已绑定代付人，读取原支付参数，不发起预下单 |
| POST `/friend-payments/:token/reconcile` | 仅已绑定代付人，查询原商户单并核验真实微信结果 |
| GET `/payments/notifications` | 仅原下单人，读取同一支付事务落库的持久通知 |

已付款、已取消、过期或无有效预约的订单不能再付。已创建本人预下单的订单不能直接切换好友代付。两位好友同时抢付只允许一个绑定；支付取消可恢复同一笔 READY 参数，未知结果只查原单，不重新创建支付。

## 数据与资金边界

迁移 `20261010060000_friend_payments` 为第33项增量迁移。`Payment.kind` 区分 SELF / FRIEND，记录付款用户外键与微信身份 HMAC 摘要；历史本人支付兼容，不伪造旧付款人信息。分享凭证32字节随机，数据库仅保存 SHA256 摘要，期限不超过原订单支付截止时间。

支付成功只认验签、解密、商户/AppID/币种/金额/流水/付款人核验后的微信通知或查单。付款、订单已支付、预约确认、审计和下单人通知同事务提交。重复通知只入账一次。订单取消后晚到账仍保留真实收款事实、进入人工核实，不恢复预约或虚报服务已安排。

管理端保留组织财务权限、微信配对及 MFA，展示本人支付/好友代付、真实付款用户 ID/昵称及成功时间，不读取或返回 OpenID、手机号、分享凭证或预支付参数。退款仍沿用原审查和原路退回流程。

## 日志保护与部署

API 自动请求和异常路径日志对分享凭证脱敏，含异常、编码和重复 namespace 路径。Nginx 只开放精确方法；能力路径访问及错误日志关闭，避免原 URI 泄露凭证；不匹配的能力路径只返回404，不转发。其他网关日志、API脱敏异常、支付审计、私网管理隔离和 TLS 验证保持启用。未开放任何新的管理权限。

发布前执行全工作区类型检查、构建、单元回归、小程序编译页面测试及真实隔离 PostgreSQL 并发集成。`scripts/verify-friend-pay-postgres.mjs` 只接受专用 `127.0.0.1:55432/friend_pay_tests` 测试库，使用临时 RSA/AES-GCM 签名通知，所有微信请求模拟，没有真实扣款或生产数据写入。

正式部署前备份数据库，以同一提交发布 API、私有管理端和入口配置，失败执行既有回退。最终状态以忽略目录内的本轮部署回执为准。小程序预览/开发版上传不等于提交审核或正式版发布。

## 真机验收

1. 两个实际微信账号分别担任下单人和好友，在可预约的真实技师/项目创建待支付订单。
2. 下单人选好友代付，主动通过微信分享卡发送；好友核对信息，本人决定是否执行真实付款。
3. 付款成功后核对好友页服务器确认、下单人订单已支付、持久消息与后台付款用户一致。
4. 测试取消付款继续原单、重复打开已付款分享、取消订单不能再付、代付人不能申请退款。
5. 微信付款确认和真实退款由用户本人操作；开发测试不代用户扣款。
