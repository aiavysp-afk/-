# 后台MFA基础交付

本轮完成微信第一因子会话上的TOTP第二因子、生产工作人员权限门禁和后台“账户安全”页。**不是完整正式后台登录交付**：微信到浏览器的安全登录/会话交接入口、真实人员与验证器验收、丢失设备的受审恢复尚未完成；真实资金仍关闭。

## 固定安全规则

- 必须是有效会话、ACTIVE用户和ACTIVE工作人员membership。客户身份不能自建后台角色或绑定后台验证器；绑定前要求微信会话创建不超过五分钟。
- 每人独立随机160bit密钥，采用[RFC6238 TOTP](https://www.rfc-editor.org/rfc/rfc6238)及[RFC4226 HOTP](https://www.rfc-editor.org/rfc/rfc4226)，SHA1/六位数字/30秒，时间窗口仅前后各一个周期。使用官方测试向量验证，未复制参考实现源码。
- 密钥只在开始绑定的响应中返回一次，AES-256-GCM加密存入数据库，不写审计/状态响应/日志。所有MFA响应no-store；前端仅保留当前组件内存，切换账号或页面会清理。不得把密钥交给在线二维码生成网站。
- 绑定十分钟到期，只允许发起绑定的同一会话激活；其他会话不能接管。已启用的因子不支持直接替换、关闭或无条件重置。
- 每次成功验证使用用户行NO KEY UPDATE锁和数据库全局计数器；同周期动态码不能在另一个会话重放，多实例并发只成功一次。该锁兼容审计外键读取，避免验证/注销倒置锁顺序。
- 五次错误后锁定五分钟，失败计数在事务提交后才抛HTTP错误，不会因错误响应回滚。锁定不延长或赋予任何会话MFA权限。
- 只提升当前Session，最多五分钟且不超过原会话过期时间。新登录不会继承其他Session的MFA，注销/禁用账号仍拒绝访问。
- NODE_ENV=production无条件要求工作人员MFA，STAFF_MFA_REQUIRED=false不能关闭生产门禁；私有验收通过STAFF_MFA_REQUIRED=true强制验证。普通客户本人订单权限不受影响，组织边界/双人退款复核仍独立检查。
- 第14批migration含状态/计数/会话期限CHECK及已启用因子不可直接更新密钥/启用时间、计数不可回退的触发器。没有新增资金POST或任意改退款状态的接口。

## 接口

四个接口均由SessionAuthGuard保护，路径前缀`/v1/auth/mfa`：

| 方法/路径 | 用途 |
| --- | --- |
| GET `/` | 查看本人绑定、锁定、当前会话有效期和门禁状态，无密钥 |
| POST `/enrollment` | 严格空JSON对象，开始绑定，返回一次性密钥及十分钟期限 |
| POST `/activate` | 严格`{code:"六位数字"}`，同会话激活并完成本次MFA |
| POST `/verify` | 严格`{code:"六位数字"}`，重新验证当前会话 |

其他参数包括verifiedUntil、用户ID、组织、密钥或金额均不能由调用方指定。错误码400参数错误、401会话/动态码/锁定/过期、403无工作人员资格、409绑定状态冲突。没有恢复、关闭和替换因子的快捷接口。

## 实际验证

- 本地开发库和独立测试库均应用第14批migration。typecheck/lint/build通过；API243项+contracts13项=256项代码测试，另有6项预览安全测试。
- 新增10项TOTP测试（包含六个RFC6238 SHA1向量及RFC4226向量）、14项MFA服务测试及2项生产/私有门禁测试。
- `test:mfa`通过实际Nest/Fastify HTTP与PostgreSQL验证：客户/未登录拒绝、密钥加密/不回显、同会话绑定、不同会话不继承、并发一次成功、重放/过期/五次锁定、生产同构门禁、跨组织/财务角色分离、注销竞态及DB防改约束。仅临时合成人员，结束自动清理，没有给真实人员绑定设备。
- 原`test:mall`/`test:wechat-db`回归通过；前者显式隔离MFA以测试业务规则，后者没有真实网络资金请求。MFA门禁另由强制true的独立HTTP测试覆盖，不能在生产沿用测试模式。
- CI已加入test:mfa；服务器实际运行版本与验收结果见[服务器验收记录](DEPLOYMENT_ACCEPTANCE_20261004.md)，不能把本地成功等同服务器成功。

## 下一步与人工门禁

1. 完成浏览器第一因子的受控微信登录/会话交接，不能让管理员在表单中粘贴访问token，也不能以Mock code冒充正式登录。
2. 负责人核验两位不同自然人的财务身份，分别完成真机微信登录和独立验证器绑定；不要共享密钥或截图。
3. 定义丢失设备的双人核验、停用会话、通知和受审恢复流程，尚未实现时不要启用真实经营。禁止直接删MfaCredential或改SQL来绕过门禁。
4. 保留加密主密钥备份，验证时间同步/备份恢复/锁定告警；TOTP不抗实时钓鱼，更高风险操作仍需进一步的强认证和审核。参考[OWASP MFA指导](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)。
5. 人工退款异常修正、outbox告警、技师真实履约及资金验收仍是独立阻断项；本轮未解除这些门禁。
6. 正式环境不能回滚到不含MFA门禁的旧应用，不能缩短或删除因子记录以恢复登录。故障应先停止受影响服务并按受审流程处理，保留会话、因子和审计。
