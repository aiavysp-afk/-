# 私有服务器验收部署

用户于2026-10-04追加全面部署授权。本方案仅用于独立私有验收，不是生产经营版，也不规避生产门禁。

## 固定边界

- `/opt/zhongyuan-daojia-acceptance`、`/etc/zhongyuan-daojia-acceptance`，独立账号`zydj-acceptance`与数据库/角色`zydj_acceptance`。
- 新API3210、管理预览3212、H5预览3213全部仅监听127.0.0.1；不添加公网Nginx、不改DNS，不碰原静享生活业务数据库、服务或微信钥证。
- `NODE_ENV=test`、Mock身份和支付；预下单/退款/补偿开关全部false。此配置不能用作公网或真机正式经营环境。
- 独立Node24.19.0运行时经官方SHA256校验；pnpm11.19.0。新进程各自受内存/CPU限制；可用磁盘低于3GiB拒绝继续安装。不会清理其他业务文件。
- 独立生成随机数据库密码、会话pepper和加密主密钥；root配置文件640，只向本项目服务组只读授权，不回显或提交仓库。
- MFA增量后私有工作人员门禁强制STAFF_MFA_REQUIRED=true；保留原随机密钥，仅补非秘密门禁变量。每次升级先备份本项目数据库再迁移，目前源版本14批；不得向旧商城库执行。

## 部署顺序

1. 核对本次main commit、CI成功、工作区干净；生成只含Git源文件与同版本dist的归档。检查包中没有.env、node_modules、证书或密钥。保留构建哈希记录。
2. 通过已知主机指纹的SSH检查端口/新目标路径/数据库归属/磁盘，备份旧Nginx及systemd配置元数据。首次部署仅在目标路径不存在时创建OWNER范围标记。
3. 上传到`releases/<完整commit>`并保留`DEPLOY_COMMIT`；执行 `bash scripts/deploy-private-acceptance.sh <完整commit>`。没有旧业务库迁移/seed。只在专用验收库应用当前14批migration与示例服务目录；已有验收环境先生成本次升级的新备份再应用新增migration，不种固定管理员身份。
4. 启动独立systemd验收服务，检查三个回环端口、health、目录API、鉴权拒绝、静态预览与原站点健康。新专用库做单独backup/恢复验证；不能用原业务备份覆盖此库。
5. 只经SSH回环隧道访问：本机5310→服务器3210，5312→3212，5313→3213。浏览器使用本机`http://127.0.0.1:5312`/5313；预览内API同源代理到验收库，不混入3100开发库。

## 停止与回滚

只停止`zhongyuan-daojia-acceptance-api/admin/h5`，不停止jingxiang服务。保留数据库和release；应用回滚只把current指向备份记载的同项目release，并重启三个验收服务。新增migration不自动回退或删表。
